# Borhan API

## Redis موقت

برای اجرای Redis اختصاصی و صرفاً حافظه‌ای از `docker compose up -d redis` استفاده کنید. پورت پیش‌فرض فقط روی `127.0.0.1:56379` در دسترس است و با `REDIS_URL=redis://localhost:56379/0` به آن متصل شوید. RDB و AOF غیرفعال‌اند و volume پایداری تعریف نشده است. از پشتیبان‌گیری، replica دارای ذخیره‌سازی و انتشار پورت روی شبکه جلوگیری کنید. پس از توقف یا راه‌اندازی مجدد Redis داده‌های جلسه ممکن است از بین بروند.

## ورود توسعه‌ای

`BORHAN_TOKEN_SECRET` را به یک مقدار محرمانهٔ طولانی و تصادفی و `DATABASE_URL` را به آدرس PostgreSQL تنظیم کنید. تنظیمات می‌توانند در فایل محلی `.env` نیز قرار گیرند؛ متغیر محیطی در صورت تنظیم اولویت دارد. برای ورود آزمایشی فقط در محیط توسعه، `BORHAN_ENV=development` را تنظیم کنید. در حالت پیش‌فرض عملیاتی، ورود تا اتصال سرویس پیامک غیرفعال است.

ابتدا به `POST /api/v1/auth/request-code` بدنهٔ `{"mobile":"09123456789"}` ارسال کنید؛ سپس به `POST /api/v1/auth/verify` بدنهٔ `{"mobile":"09123456789","code":"1234"}` بفرستید. پاسخ شامل `access_token` و `token_type` است. توکن را به صورت `Authorization: Bearer <access_token>` در درخواست‌های محافظت‌شده ارسال کنید. کد ثابت فقط برای توسعه است.

## راه‌اندازی و بازگشت نسخه

PostgreSQL و Docker باید در دسترس باشند. در PowerShell از ریشهٔ پروژه:

```powershell
.\venv\Scripts\python.exe -m pip install -r requirements.txt
$env:DATABASE_URL = "postgresql://USER:PASSWORD@localhost:5432/borhan"
$env:REDIS_URL = "redis://127.0.0.1:56379/0"
$env:BORHAN_TOKEN_SECRET = "یک-مقدار-محرمانه-طولانی-و-تصادفی"
$env:BORHAN_ENV = "development"
docker compose up -d redis
.\venv\Scripts\python.exe -m app.migrate
.\venv\Scripts\python.exe -m uvicorn app.main:app --port 8001
```

نشانی و رمز پایگاه داده و کلید امضا را با مقادیر واقعی و محرمانه جایگزین کنید. حالت توسعه را در محیط عملیاتی فعال نکنید. برای rollback نسخهٔ قبلی برنامه را جایگزین و مسیرهای جدید را غیرفعال کنید؛ جدول `users` را برای حفظ حساب‌ها حذف نکنید. پاکسازی یا توقف Redis داده‌های جلسه‌های موقت را غیرقابل‌بازیابی می‌کند؛ برای پاکسازی عمدی Redis اختصاصی ابتدا اثر آن را بر جلسه‌های فعال بررسی کنید.

## الزامات حفظ حریم خصوصی

پیش از استقرار، تمام مسیر داده را بررسی کنید:

- در reverse proxy، بافر دیسکی درخواست را غیرفعال و ثبت بدنه، نام فایل، توکن و مسیرهای حاوی شناسهٔ قرارداد را حذف یا ماسک کنید.
- Redis اختصاصی را بدون RDB، AOF، volume، replica دارای ماندگاری و پشتیبان اجرا کنید و دسترسی شبکه را محدود نگه دارید.
- swap، crash dump، snapshot و telemetry زیرساخت را به‌گونه‌ای تنظیم کنید که حافظهٔ حاوی متن قرارداد روی دیسک ذخیره نشود.
- در سرویس مدل و هر ابزار ثبت یا رصد، ذخیرهٔ ورودی، پاسخ و بدنهٔ درخواست را غیرفعال کنید. تنظیمات سرویس مدل باید جداگانه بررسی شود؛ بدون آن، عدم ماندگاری سرتاسری تضمین نمی‌شود.

## تحلیل ریسک بند قرارداد

برای تحلیل فایل، پس از ورود توکن را در هدر Bearer قرار دهید و یک فایل `PDF` یا `DOCX` حداکثر ۱۵ مگابایت را در فیلد `file` به `POST /api/v1/contracts/upload` ارسال کنید. پاسخ شامل `contract_id`، تعداد و آرایهٔ بندها و متن خروجی خام مدل در `result` است. هر آپلود جلسه‌ای جداگانه می‌سازد.

بندهای بسیار کوتاه، اطلاعات صرفاً شناسنامه‌ای، مقدمه‌های بدون تعهد و عنوان‌های خالی با `type: informational`، مقدار `result: null` و دلیل در `skip_reason` ثبت می‌شوند و به مدل ارسال نمی‌شوند. سایر بندها با `type: risk_analysis` و پاسخ مدل در `result` برمی‌گردند. اطلاعاتی بودن یک بند به معنی تأیید حقوقی یا تضمین نبود ریسک نیست.

مالک می‌تواند تا دو ساعت با `GET /api/v1/contracts/{contract_id}` جلسه را بازیابی و با `DELETE /api/v1/contracts/{contract_id}` فوراً حذف کند. جلسهٔ ناموجود، منقضی یا متعلق به کاربر دیگر با 404 پاسخ داده می‌شود. خطای فایل نامعتبر 415 یا 422، فایل بزرگ‌تر از حد مجاز 413 و خطای سرویس مدل 502 یا 504 است. مسیرها و قالب پاسخ در `/docs` قابل مشاهده‌اند.

سرویس مستقیماً به API مدل روی پورت ۸۰۰۰ متصل می‌شود. تنظیمات زیر را مطابق سرویس مدل تنظیم کنید:

- `LLM_BASE_URL`: آدرس پایهٔ API، بدون `/chat/completions`؛ پیش‌فرض `http://127.0.0.1:8000/v1`.
- `LLM_MODEL`: نام مدلی که سرویس می‌شناسد؛ پیش‌فرض `contract-risk-model`.
- `LLM_API_KEY`: کلید API، در صورت نیاز سرویس.
- `LLM_TIMEOUT_SECONDS`: مهلت پاسخ به ثانیه؛ پیش‌فرض `120`.

اگر مدل روی پورت ۸۰۰۰ اجرا می‌شود، بک‌اند را روی پورت دیگری اجرا کنید:

```powershell
$env:LLM_BASE_URL = "http://127.0.0.1:8000/v1"
$env:LLM_MODEL = "contract-risk-model"
.\venv\Scripts\python.exe -m uvicorn app.main:app --port 8001
```

درخواست `POST /api/v1/contract-risk`:

```json
{"clause": "کارفرما موظف است مبلغ قرارداد را ظرف ده روز پس از تحویل پرداخت کند."}
```

پاسخ شامل متن خام خروجی مدل است:

```json
{"result": "مناسب"}
```

مستندات تعاملی در `http://localhost:8001/docs` در دسترس است. این اتصال به سرویس Chat Completions نیاز دارد؛ خروجی و قابلیت ارائهٔ احتمال یا میزان اطمینان به سرویس و مدل بستگی دارد.
