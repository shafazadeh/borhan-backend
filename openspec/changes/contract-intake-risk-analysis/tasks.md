# Tasks

## 1. پیکربندی و زیرساخت

- [x] 1.1 وابستگی‌ها و تنظیمات PostgreSQL، Redis، پردازش سند و امضای توکن را تعریف کن؛ راه‌اندازی با تنظیمات معتبر و خطای مشخص برای نبود کلید امضا را بررسی کن.
- [x] 1.2 مهاجرت جدول کاربران را با شناسه، شماره موبایل نرمال‌شده و یکتا و زمان ایجاد اضافه کن؛ ساختار جدول و محدودیت یکتایی را بررسی کن.
- [x] 1.3 تنظیمات اجرای Redis حافظه‌ای بدون RDB، AOF، volume پایدار و پشتیبان‌گیری را همراه با راهنمای اتصال مستند کن؛ تنظیمات مؤثر و دسترسی محدود شبکه را بررسی کن.

## 2. احراز هویت موبایلی

- [x] 2.1 درخواست کد و تأیید شماره را با نرمال‌سازی موبایل و ایجاد یا بازیابی اتمیک کاربر پیاده کن؛ ورود دوباره با یک شماره باید به همان حساب منجر شود.
- [x] 2.2 کد ثابت `1234` را به حالت توسعهٔ صریح محدود کن و ورود بدون ارائه‌دهندهٔ واقعی در سایر محیط‌ها را ببند؛ رفتار هر دو محیط را بررسی کن.
- [x] 2.3 محدودیت نرخ و تعداد تلاش درخواست و تأیید کد را اعمال کن؛ درخواست‌های بیش از حد و کد نامعتبر باید بدون صدور توکن رد شوند.
- [x] 2.4 توکن Bearer امضاشده و زمان‌دار و وابستگی تشخیص کاربر را اضافه کن؛ توکن نامعتبر، منقضی و کاربر ناموجود باید رد شوند.
- [x] 2.5 قرارداد مسیرهای ورود و تنظیم حالت توسعه و کلید امضا را مستند کن؛ نمونهٔ درخواست و پاسخ در مستندات API قابل مشاهده باشد.

## 3. دریافت و استخراج سند

- [x] 3.1 دریافت multipart جریان‌محور و محدود به RAM برای یک فایل تا سقف ۱۵ مگابایت را پیاده کن؛ فایل بزرگ‌تر یا چندفایلی رد و فایل موقت دیسکی ایجاد نشود.
- [x] 3.2 نوع واقعی، امضا و ساختار PDF و DOCX را اعتبارسنجی و محدودیت‌های تعداد و حجم بازشدهٔ ZIP و نسبت فشرده‌سازی را اعمال کن؛ اسناد نامعتبر، رمزدار یا خطرناک پیش از مدل رد شوند.
- [x] 3.3 استخراج PDF و DOCX از حافظه را با محدودیت منابع و پاکسازی در خطا پیاده کن؛ سند بدون متن قابل استخراج خطای مناسب بدهد و داده‌ای روی دیسک باقی نماند.
- [x] 3.4 نرمال‌سازی فارسی و بندبندی ساختار حقوقی را با ترتیب و UUID مستقل هر بند اضافه کن؛ ماده‌ها، بندها، تبصره‌ها و متن بدون مرزبندی مشخص نتیجهٔ قابل مشاهده داشته باشند.

## 4. تحلیل و جلسهٔ موقت

- [x] 4.1 adapter مدل فعلی و محدودیت هم‌زمانی قابل تنظیم را به تحلیل بندها وصل کن؛ پاسخ خام مدل در بند مربوط بازگردد و خطای هر بند از تکمیل تحلیل جلوگیری کند.
- [x] 4.2 مخزن جلسه را با کلید متعلق به کاربر و ذخیرهٔ اتمیک `EX 7200` پیاده کن؛ TTL واقعی و ساخته‌نشدن جلسهٔ ناقص را بررسی کن.
- [x] 4.3 مسیر آپلود احراز هویت‌شده را به استخراج، تحلیل و ذخیرهٔ جلسه وصل کن؛ آپلود موفق جلسهٔ جدید و پاسخ کامل ایجاد کند و هر بار شناسهٔ متفاوت بدهد.
- [x] 4.4 مسیرهای GET و DELETE احراز هویت‌شده را بر اساس شناسهٔ کاربر توکن اضافه کن؛ مالک پس از ورود مجدد بتواند جلسه را بازیابی یا با 204 حذف کند و کاربر دیگر به آن دسترسی نداشته باشد.
- [x] 4.5 پاسخ 404 جلسهٔ منقضی یا ناموجود و عدم تمدید TTL هنگام خواندن را پیاده کن؛ متن راهنمای آپلود مجدد و مقدار TTL را بررسی کن.
- [x] 4.6 قالب پاسخ، احراز هویت و خطاهای مسیرهای قرارداد را مستند کن؛ مستندات تعاملی شامل هر سه مسیر و خروجی واقعی مدل باشد.

## 5. حریم خصوصی و استقرار

- [x] 5.1 ثبت بدنه، نام فایل، متن قرارداد، توکن و شناسهٔ جلسه را در لاگ برنامه و گزارش خطا حذف یا ماسک کن؛ خروجی لاگ درخواست‌های موفق و ناموفق بدون این داده‌ها باشد.
- [x] 5.2 پیش‌نیازهای reverse proxy، حافظهٔ سیستم، crash dump و Redis و همچنین غیرفعال‌سازی ثبت ورودی و پاسخ در سرویس مدل و ابزارهای رصد را مستند کن؛ چک‌لیست استقرار همهٔ این مرزها را پوشش دهد.
- [x] 5.3 مراحل اعمال مهاجرت، پیکربندی سرویس‌ها و rollback بدون حذف حساب‌ها را مستند کن؛ فرمان‌ها و پیش‌نیازهای اجرا با تنظیمات پروژه هم‌خوان باشند.
